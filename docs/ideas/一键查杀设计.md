# 一键查杀（批量屏蔽扩散扫描）

> 设计日期：2026-07-30  
> 状态：待实现

## 目标

从已有的屏蔽记录出发，自动发现关联的垃圾账号，批量导出一份名单去 X 设置中导入屏蔽。

## 数据来源

### 1. 回复文本中的 @引流
从 `blockHistory` 每条记录的 `replyText` 中提取 `@xxx` 账号。

示例：
```
"比她好看的7a没她骚v5比她骚的没她好看 @paz_olmo m2M"
                                       ↑ 提取 @paz_olmo
```

### 2. 被屏蔽账号的 Bio 链接
对每个被屏蔽账号（以及 @引流目标），调 API `users/show.json` 检查 bio 是否含推广链接（linktr.ee、onlyfans、f5k1.top 等）。

## 检测逻辑

```
屏蔽记录（最多100条）
    │
    ├─ 提取 replyText 中的 @xxx → 加入疑似名单
    │
    └─ 对每个引流目标 @xxx → 调 API 拉 bio → 检查是否有推广链接
                                       │
                                       └─ 有链接 → 确认垃圾号，加入最终名单
```

## 输出

最终名单去重 → 导出 CSV（每行一个 `@handle`）→ 去 X 设置 → 隐私与安全 → 屏蔽 → 导入

## 技术方案

### 方案 A：block.html 页面按钮触发
- 在屏蔽管理页加「一键查杀」按钮
- 点击后通过 `chrome.tabs.sendMessage` 通知 content script 执行扫描
- 扫描结果展示扫描数 + 确认弹窗
- 确认后导出 CSV 下载

### 方案 B：后台定时扫描
- 跟随用户浏览节奏，后台异步处理
- 每次扫描结果存入 storage
- block.html 页面展示已发现的疑似账号

## 注意事项

- 调 API 拉 bio 时要控制并发数（3-5 个），避免 rate limit
- 扫描结果去重，避免重复名单
- CSV 格式：一行一个 `@handle`，不带表头
- X 导入屏蔽上限约 5000 个
