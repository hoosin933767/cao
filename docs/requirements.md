## 需求记录

### R1. 屏蔽垃圾回复（核心需求）

**用户原话（2026-07 起陆续确认）：**
- "全自动检测 X/Twitter 垃圾回复，基于多维特征引擎一键屏蔽"（商店描述）
- "这个也被屏蔽了，企业账号是真的可以排除掉，蓝V是个人用户，黄色的是企业用户"（→ 企业金V应跳过检测）
- "其实根源是@的规则我们没做好……我们的创始人之一 @claybavor 经常将 Sierra 描述为生产快乐客户的机器"（→ 正常对话中的 @ 不应判定为引流）
- "根本没有理由"（→ 对 Cecilia Hsueh 被误杀的不满，要求正常对话不得误伤）

**确认结果：**
- 检测对象：推文详情页的回复（article）
- 企业/组织认证（金V）账号跳过检测；个人蓝V 不跳过
- @ 引流判定必须命中推广关键词才扣分，普通对话 @ 不扣分
- 误杀优先级高于漏杀（宁放过，不误伤）

### R2. 屏蔽管理页

**用户原话：**
- "4条记录"、"都没有@账号"（→ 需要能查看屏蔽记录）
- "有4条"（→ 记录列表需求）
- "没有这个功能啊"（→ 用户期望在管理页看到每条记录的特征，当前无此功能）

**确认结果：**
- block.html 提供屏蔽记录列表（分页 20 条/页）
- 显示：头像、显示名、@handle、回复文本、推文链接、屏蔽时间
- 解除屏蔽：单条解除 + 全量解除

### R3. 一键查杀（暂停开发）

**用户原话：**
- "我想做，但又想了一下，目前屏蔽没啥人用后面开发也是浪费钱"
- "引流有几种：1、@账号 2、BIO有网址"
- "批量屏蔽慢一些没关系"

**确认结果：**
- 暂缓开发，设计文档已保存至 `docs/ideas/一键查杀设计.md`
- 后续用户有需求再启动

### R4. 回测样本库

**用户原话：**
- "这个也给我提了一个醒，每个不同的样本要保留一份，用来回测试用的"
- "多拿几个数据回测一下，我对你的智商不是很放心"

**确认结果：**
- 建立 `docs/samples/` 样本库 + `scripts/regression.js` 回归脚本
- 每次改动检测引擎必须跑回测

### R5. 检测准确性修复（2026-08-02）

**用户原话：**
- "有bug，发现屏蔽了几个账号，右下角不显示屏蔽了几个，连屏蔽的字都没有"（→ 状态显示）
- "[CAO] saveBlockHistory failed after 3 attempts: Error: Extension context invalidated."（→ 扩展更新后旧页面失效）
- "有用户问，关键词是模糊匹配吗？"（→ 需要文档说明匹配规则）

**确认结果：**
- 修复评分钳制 Math.min/max 错误（13 处）
- 修复拼音绕过（sao→骚）
- 新增水军模板检测（同句多账号 -2 分）
- 增加 context invalidated 提示

## 验收标准

1. 正常用户（含正常中文 @ 对话）不得被屏蔽
2. 企业金V 不参与检测
3. 典型垃圾号（涩/骚/同城/免费/破处/水军模板/拼音绕过）必须被识别
4. 每次引擎改动跑 `node scripts/regression.js`，38 条样本全绿
5. 屏蔽记录、右下角状态正常显示
